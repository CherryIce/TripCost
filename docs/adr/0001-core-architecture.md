# ADR-0001：V1 核心架构与数据语义

- 状态：已接受
- 日期：2026-08-17
- 适用：M1～M9

## 决策

### 金额与汇率

- 账务金额以“十进制系数 + scale + ISO 4217 币种”表达；数据库持久化规范化十进制字符串和币种，不使用 `double` 作为事实值。
- 计算过程使用十进制库；展示时按币种小数位和 Locale 舍入，展示字符串不参与再次计算。
- 汇率统一定义为 `1 baseCurrency = rate quoteCurrency`，倒数转换显式进行并保留来源精度。
- 每笔消费保存不可变的汇率、费用规则、预计结果快照；当前配置变化不得回写历史。

### 标识、时间和数据库迁移

- 业务实体主键使用客户端生成的 UUID；数据库自增序号只能用于本地排序，不能作为同步身份。
- 时间以 UTC ISO-8601 或 UTC epoch 保存；仅在界面边界转换到设备时区。汇率的“数据日期”和“设备获取时间”分别保存。
- Drift schema 从版本 1 开始；每次 schema 变更同时提交迁移、schema 导出和旧版本升级测试。破坏性重建只允许用于未发布开发数据，并必须显式记录。
- 删除采用墓碑语义；票据文件是私有目录资源，只在数据库中保存相对引用。

### 分层与状态

- `features` 只能通过 Repository 使用网络、数据库和平台能力；DTO、数据库行和页面状态不互相泄漏。
- Riverpod 的 `Notifier`/`AsyncNotifier` 组织页面状态；纯计算保持无 Flutter 依赖并可表驱动测试。
- Repository 对外返回领域值或显式失败，不吞错、不以空列表伪装失败。
- 错误至少区分：验证、无可用汇率、网络、缓存、权限、存储、平台能力、同步冲突和未知错误；日志仅记录脱敏上下文与关联 ID。

### Flutter/Swift 契约

- Pigeon schema 是 Flutter/Swift 边界的单一事实源；生成产物提交仓库，并通过脚本重复生成。
- Pigeon DTO 带 `contractVersion`。破坏性变化提升版本并提供兼容迁移或明确阻断。
- Swift 只负责 Vision、CloudKit、App Group/Widget 与系统分享；金额解析、预算和费用逻辑留在 Dart。

### CloudKit 增量同步

- Drift/SQLite 是事实源，CloudKit private database 是可关闭的增量同步层；同步失败不阻断本地读写。
- 每条记录携带稳定 UUID、逻辑更新时间、设备/变更 ID、删除墓碑和 schema 版本；批次应用必须幂等。
- 每个 record zone 保存独立 server change token。只有本地事务成功应用整批变化后才推进游标。
- 普通字段采用确定性的 last-write-wins；实际入账金额的不同非空值不得静默覆盖，必须产生可展示冲突。
- 墓碑至少保留到所有已知游标越过删除点；最终保留周期在 TC-070 前另立 ADR，未确定前不做物理删除。

## 后果

- 初期模型和测试工作量增加，但账务精度、历史可追溯、离线和同步语义在功能开发前稳定。
- 正式名称、标识符、CloudKit zone、墓碑周期和备份加密仍可延后，不影响 M1 工程骨架。
