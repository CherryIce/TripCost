# ADR-0002：CloudKit 墓碑、游标与冲突语义

- 状态：已接受
- 日期：2026-08-17
- 适用：M7～M9

## 决策

- Drift/SQLite 继续作为事实源；CloudKit private database 只保存可重建的结构化同步记录。
- 每条同步记录包含稳定业务 ID、实体类型、schemaVersion、UTC 修改时间、deviceId、changeId 和删除墓碑。票据本地路径与原图永不进入同步 payload。
- 每个批次先幂等 push，再按 record zone change token pull。只有整批远端变化在同一个本地事务内成功应用后，才持久化新游标。
- 普通字段采用确定性的 last-write-wins：先比较 UTC 修改时间；时间相同时比较 changeId。重复 changeId 视为同一变化。
- 消费的 `actual_final_amount` 若本地与远端均为非空、值不同且本地尚未同步，则不静默覆盖。双方完整 payload 写入冲突表，用户选择后生成新的本地版本再次同步。
- 删除使用墓碑，M7 不做物理删除。首版保留期定为至少 180 天；正式清理还必须确认所有已知设备游标已越过删除变化。无法证明时继续保留。
- 同步关闭、无 iCloud、网络失败、配额异常或单批失败均不阻断本地读写；失败状态、错误码、退避时间和最近成功时间在本地持久化。

## 后果

- 旧设备不会用较早的远端记录复活已删除实体。
- 游标与数据应用具备事务边界；崩溃后最多重复拉取，不会跳过未落库变化。
- 实际入账冲突需要用户处理，但不会丢失任一侧值。
- 180 天只是最低安全窗口，不是自动物理删除授权；后续设备注册/退役协议完成前不清除墓碑。
